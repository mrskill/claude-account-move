# claude-account-move

Версия 0.1.1. Перенос Claude Code (приложение для Mac и CLI) с одной учетной
записи Claude на другую без потери сессий, с проверкой после переноса, что
ничего не пропало.

Это независимый инструмент. Он не является продуктом Anthropic и не одобрен
Anthropic. Устройство хранилища, которое он читает, является внутренней деталью
приложения Claude и может измениться в новых версиях приложения.

Автор: **Mr. Skill** ([@mrskill](https://github.com/mrskill))

English version: [README.md](README.md)

## Что делает

| Команда | Когда | Что происходит |
|---|---|---|
| `prepare` | до выхода из учетной записи | Гонит проверки готовности, записывает снимок "до" для этого переноса (только метаданные), печатает вердикт. Один проход. |
| `finish` | после входа в приложение и `claude /login` | Ждет, пока учетная запись CLI сравняется с учетной записью приложения, затем сверяет хранилище со снимком ИМЕННО этого переноса и печатает вердикт. |
| `sync` | необязательная починка | Копирует карточки сессий, которых нет в папке новой учетной записи. По умолчанию холостой прогон (печатает файлы). `sync --apply` добавляет файлы, `sync --undo` удаляет ровно те файлы, которые журнал доказуемо добавил; только эти операции пишут в хранилище Claude. |

Проверки судят по именам и идентификаторам, записанным до переноса, а не только
по количеству (каждое число печатается со своим знаменателем):

- хранилище прочитано полностью (нет нечитаемой карточки, транскрипта или файла задач);
- учетная запись-источник читается (переносу нужна известная точка старта), а
  файл настроек, если он есть, читается;
- каталог, в который пишет приложение, существует и доступен для записи по правам;
- приложение обновляет карточки (медианное отставание живых сессий);
- нет сессии, удаленной в панели, у которой осталась живая карточка;
- в активной папке лежит самая свежая копия каждой карточки;
- ни у одной карточки не потерян `cliSessionId`, пока существует ее транскрипт
  (сессия есть на диске, но открыться не сможет);
- у одной сессии нет двух разных файлов карточки;
- после переноса: каждое имя карточки, каждая метка удаления и каждая задача по
  расписанию, записанные до переноса, на месте; копия каждой карточки в целевой
  папке привязана к тому же идентификатору сессии, что был записан, и не старше;
  у каждого записанного транскрипта сохранились размер и последнее сообщение
  (судится по каждой сессии, а не по одному общему максимуму); настройки не
  изменились (разрешения и хуки сравниваются по отпечатку полного содержимого,
  поэтому замена одной записи другой видна); обе учетные записи совпадают с целевой.

Значение, которое можно было измерить до переноса и нельзя измерить после, это
провал, а не успех.

## Чего не делает

- Никогда не входит в учетную запись за вас и не просит, не читает и не хранит
  пароль или токен. В приложение вы входите сами и сами выполняете `claude /login`.
  Файлы `~/.claude.json` и `config.json` приложения разбираются целиком как JSON,
  но сохраняются только идентификаторы учетной записи и организации.
- `prepare`, `finish` и проверки ничего не меняют в хранилище Claude и в ваших
  настройках. Все, что они пишут, лежит в каталоге состояния (см. ниже). Они не
  создают даже пробный файл в хранилище. К хранилищу прикасаются только
  `sync --apply` (добавляет файлы карточек) и `sync --undo` (удаляет файлы,
  которые журнал доказуемо добавил командой `--apply`).
- Не переносит задачи по расписанию: `finish` сообщает о записанных задачах,
  которых нет в новой учетной записи, но перенос остается за вами.
- Не выбирает за вас между двумя разными идентификаторами сессии за одним именем
  карточки: `sync` перечисляет такие конфликты, ничего для них не копирует и
  завершается кодом `3`.
- Не верит явному `--active-pair` вслепую: учетная запись в нем должна быть той,
  в которую вошло приложение, иначе команда останавливается с кодом `2`.

## Требования

- macOS (пути соответствуют приложению Claude для macOS);
- Python 3.9 или новее, только стандартная библиотека;
- приложение Claude и Claude Code CLI.

## Установка

```sh
git clone https://github.com/mrskill/claude-account-move.git
cd claude-account-move
./claude-account-move --version      # claude-account-move 0.1.1
```

Либо скачайте архив релиза, распакуйте и запускайте `./claude-account-move` из
распакованного каталога. Чтобы вызывать из любого места, сделайте ссылку в
каталоге из `PATH`: `ln -s "$PWD/claude-account-move" /usr/local/bin/claude-account-move`.
Входной скрипт раскрывает ссылку, поэтому пакет рядом с ним находится.

## Перенос по шагам

Команды ниже запускаются как `./claude-account-move` из клонированного или
распакованного каталога. Если вы сделали ссылку в `PATH`, уберите `./`.

1. В терминале, пока вы еще в старой учетной записи:

   ```sh
   ./claude-account-move prepare
   ```

   Код `0` значит готово. Любой другой: прочитайте строки `FAIL`, устраните
   причину, запустите `prepare` снова. Снимок, снятый при неготовом вердикте,
   хранится для разбора, но `finish` сам его не выбирает.
2. Выйдите из приложения Claude и войдите с новой учетной записью. Это делаете вы.
3. В терминале войдите в CLI с той же новой учетной записью: `claude /login`.
4. Выполните:

   ```sh
   ./claude-account-move finish
   ```

   Команда ждет до 15 минут (`--wait-login СЕКУНДЫ`), пока учетная запись CLI
   сравняется с учетной записью приложения, затем проверяет. Код `0` значит, что
   все доехало.
5. Если `finish` пишет, что имен не хватает в папке новой учетной записи (код `3`,
   падает `target_names`, нигде ничего не пропало), скопируйте их и проверьте снова:

   ```sh
   ./claude-account-move sync            # холостой прогон: печатает файлы, которые скопирует
   ./claude-account-move sync --apply    # копирует; только добавляет файлы
   ./claude-account-move finish
   ```

   Затем один раз перезапустите приложение Claude: список сессий оно читает
   только при старте. Перезапуск завершает идущие сессии, сохраните работу заранее.

Полезные ключи: `--json` (каждая команда и каждый исход, включая отказы, печатает
ровно один JSON-отчет в stdout; текст для человека идет в stderr),
`--home КАТАЛОГ` (проверить другой домашний каталог), `--state-dir КАТАЛОГ`,
`--wait-sync СЕКУНДЫ`, `--allow-same-account` (повторный вход в ту же учетную
запись), `--move-id ID`, `--max-age-hours N` (по умолчанию 72), `--active-pair
УЧЕТКА/ОРГАНИЗАЦИЯ` (если по журналу приложения пару определить нельзя; учетная
запись должна быть той, в которую вошло приложение), `prepare --full-copy`
(дополнительно скопировать все файлы карточек в снимок; объемно).

### Необязательно: собственная задача синхронизации

Если у вас работает фоновая задача, выравнивающая папки учетных записей, пусть она
обновляет время изменения файла при каждом запуске, а вы передадите его ключом
`--heartbeat ФАЙЛ` (или переменной `CLAUDE_ACCOUNT_MOVE_SYNC_HEARTBEAT`).
Тогда `prepare` требует, чтобы файл был моложе `--sync-max-age-min` (по умолчанию
30), а `finish` отвечает `5` ("подождать") вместо `3`, пока задача жива и имена
еще доезжают. Без отметки эта проверка пропускается.

## Коды выхода

| Код | Смысл |
|---|---|
| 0 | `prepare`: готово к переносу. `finish`: все доехало, все проверки прошли. `sync`: выполнено либо холостой прогон без замечаний. |
| 1 | Внутренняя ошибка инструмента или не удалась обязательная запись состояния (снимок, указатель, журнал, ссылка внутри каталога состояния). Не говорит ни о потере, ни о готовности. Сбой сохранения необязательного файла JSON-отчета лишь предупреждается в stderr. |
| 2 | Ошибка ввода: нет команды, каталог состояния пересекается с хранилищем Claude, вашими настройками или журналами, неверный или чужой `--active-pair`, журнал, который нельзя использовать (нечитаем, нет записи begin, принадлежит другому домашнему каталогу). |
| 3 | Провал по существу. `prepare`: красная проверка готовности. `finish`: чего-то не хватает или оно отличается (карточка, привязка целевой карточки, транскрипт, метка удаления, задача, настройки, учетная запись, папка). `sync`: вход прочитан не полностью, целевая папка не определена, копирование не удалось, найден конфликт, либо (`--undo`) в журнале оборванная или поврежденная часть или названы файлы, не доказанные как наши (они сохраняются). |
| 4 | Хранилище не найдено (нет папки поддержки приложения Claude или в ней нет ни одной папки учетная запись/организация). |
| 5 | `finish`: ничего не потеряно, но доставлено еще не все, а ваша задача синхронизации жива. Подождите и запустите снова. |
| 6 | `finish`: ожидание входа истекло. Причина в `login.reason` JSON-отчета: `cli_lags`, `app_not_switched`, `identity_invalid`. |
| 7 | `finish`: нет годного снимка "до" этого переноса (нет, поврежден, не готов, без учетной записи-источника, старше `--max-age-hours`, другой домашний каталог, неизвестный `--move-id`). |

При нескольких причинах код выбирается по команде в таком порядке: `prepare`:
2, 4, 1, 3, 0. `finish`: 2, 4, 7, 6, 3, 5, 0 (хранилище без папок учетных записей
дает 4, даже если снимка нет). `sync`: 2, 4, 1, 3, 0.

## Где лежит состояние

Все, что инструмент пишет, кроме копируемого командой `sync --apply` в хранилище
Claude, лежит в `~/.claude-account-move/` (переопределяется переменной
`CLAUDE_ACCOUNT_MOVE_HOME` или ключом `--state-dir`):

```
moves/<id-переноса>/before.json      метаданные карточек, метки удаления, учетные записи, id задач, размеры и время последних сообщений транскриптов, счетчики и отпечатки настроек
moves/<id-переноса>/manifest.json    контрольная сумма before.json, признак готовности, отпечаток домашнего каталога, время создания
moves/<id-переноса>/report-*.json    JSON-отчеты каждого запуска
moves/<id-переноса>/cards-copy/      только при prepare --full-copy
current-ready-move-id                самый новый готовый снимок
sync-<время>-<id>.jsonl              журнал одного sync --apply (каждый запуск в новом файле)
```

В обычном режиме только метаданных в снимке есть идентификаторы учетных записей и
организаций, идентификаторы сессий и имена файлов карточек. Заголовков, текста
сообщений, адреса почты и пути вашего домашнего каталога в нем нет (только его
короткий отпечаток). С `prepare --full-copy` в снимок попадают и полные копии
файлов карточек и задач, а в них могут быть заголовки, запросы и другие личные
поля. В любом случае считайте каталог личным и не публикуйте его.
Инструмент отказывается работать с каталогом состояния, пересекающимся с
хранилищем Claude, вашими настройками Claude или журналами, и отказывается писать
через ссылку в любом месте внутри него. Кэши байт-кода он не пишет.

## Как откатиться

- `prepare`, `finish` и проверки ничего не меняли, откатывать нечего. Каталог
  `moves/<id-переноса>` можно удалить в любой момент.
- `sync --apply` только добавляет файлы и ничего не перезаписывает. Убрать ровно
  добавленное: `./claude-account-move sync --undo ~/.claude-account-move/sync-<время>-<id>.jsonl`.
  Файл удаляется, только если журнал доказывает, что его опубликовал этот запуск
  (то же устройство и inode, что у подготовленной копии, то же содержимое) и
  журнал принадлежит этому домашнему каталогу. Файл, у которого лишь совпали имя
  или байты (карточка, записанная приложением, или восстановленная вами),
  сохраняется и помечается как неоднозначный. Прерванный журнал используется до
  последней полной строки, оборванная часть сообщается. Сам откат пишет в
  хранилище (удаляет), поэтому на него не распространяется обещание "только
  чтение" выше.
- Папки старой учетной записи не трогаются. Чтобы вернуться, снова войдите в
  приложение и в CLI со старой учетной записью.

## Ограничения

- Везде только чтение, кроме `sync --apply` (добавляет файлы карточек и может
  создать папку режима агента для целевой учетной записи, если ее еще нет) и
  `sync --undo` (убирает добавленное командой `--apply`).
- Файлы задач по расписанию должны иметь ожидаемую форму (список объектов с id);
  иное сообщается как нечитаемое наблюдение, а не как "задач нет".
- Активная папка берется по последнему упоминанию в журнале приложения
  (`~/Library/Logs/Claude/main.log`), потому что организация не всегда совпадает с
  той, что в `~/.claude.json`. Если журнала нет, передайте `--active-pair`.
- Доступ проверяется по битам прав, запись не пробуется, поэтому монтирование
  только для чтения, которое все же сообщает право записи, не обнаруживается.
- Устройство хранилища выведено наблюдением за приложением, а не из документации.
  Новые версии приложения могут его изменить.
- Проверялись Python 3.9 и 3.12; поддерживается только macOS.

## Разработка

```sh
python3 -m unittest discover -s tests
```

Тесты собирают синтетический домашний каталог во временной папке и никогда не
трогают настоящий. Проверка приватности испытывает свой сканер только на выдуманных
словах; настоящий список приватных имен хранится вне репозитория. Чтобы применить
такой список тоже, укажите переменной `CLAUDE_ACCOUNT_MOVE_DENYLIST` файл со
строками `re:<шаблон>` или `cs:<шаблон>`.
